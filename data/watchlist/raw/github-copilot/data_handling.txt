•	Business/Enterprise training: GitHub states explicitly that Copilot Business and Copilot Enterprise data is not used to train GitHub's models. (https://github.com/features/copilot/copilot-business)
	•	Individual-plan training changed in 2026: From April 24, 2026, GitHub began using interaction data—including inputs, outputs, code snippets and associated context—from Copilot Free, Pro and Pro+ users to train and improve AI models unless those users opt out. (https://github.blog/news-insights/company-news/updates-to-github-copilot-interaction-data-usage-policy/)
	•	Enterprise implication: The 2026 training-policy change explicitly does not apply to Copilot Business or Enterprise. (https://github.blog/changelog/2026-03-25-updates-to-our-privacy-statement-and-terms-of-service-how-we-use-your-data/)
	•	Retention — IDE chat/completions: For Business and Enterprise customers, GitHub's current default is that prompts and suggestions accessed through IDE chat and code completions are not retained; user engagement data is retained for two years, while feedback data is retained as needed for its purpose. (https://github.com/features/copilot/plans)
	•	Important retention distinction: Retention differs depending on how Copilot is accessed and which feature is used. GitHub states that some Copilot features retain prompts and suggestions because conversation history is needed for functionality. (https://github.com/features/copilot)
	•	Data collected: GitHub identifies Copilot interaction data such as prompts/inputs, suggestions/outputs, code snippets and associated context as data that can be processed, depending on plan and feature. (https://github.blog/changelog/2026-03-25-updates-to-github-privacy-statement-and-terms-of-service-how-we-use-your-data/)
	•	GitHub also processes personal/account information for purposes including billing/account management, legal obligations, abuse detection, virus scanning, terms-of-service enforcement and aggregated reporting. (https://github.com/features/copilot)
	•	Repository context: Copilot can draw context from repositories, pull requests, issues and other GitHub data structures, particularly when the repository is hosted on GitHub. (https://github.com/features/copilot/copilot-business)
	•	Content exclusion: Enterprise administrators can use policies to control which features, models and MCP servers are available and can configure restrictions including excluding particular files from Copilot processing. (https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/enable-copilot/set-up-for-enterprise)
	•	Third-party model providers: Copilot is now multi-model and supports models from multiple providers. GitHub documents model availability and model-specific restrictions, including models from OpenAI, Anthropic and other providers. (https://docs.github.com/en/copilot/reference/ai-models/supported-models)
	•	Data residency: GitHub Enterprise Cloud offers data residency capabilities, and FedRAMP-compatible model enforcement is specifically available for GitHub Enterprise Cloud with US data residency. (https://docs.github.com/en/copilot/concepts/models/fedramp-models)
	•	Subprocessors: GitHub publishes a list of subprocessors that may process personal information on behalf of GitHub. (https://docs.github.com/en/site-policy/privacy-policies/github-subprocessors) Because Copilot uses third-party AI model providers, procurement should review the current GitHub subprocessor list and the applicable Copilot terms rather than assuming all inference occurs exclusively inside Microsoft's own infrastructure.
	•	Overall data-handling assessment: LOW-to-MEDIUM risk for Business/Enterprise when configured correctly. The strongest positive control is the explicit no-training commitment for Business/Enterprise. The principal risks are the amount of source-code context Copilot can access, feature-specific retention, third-party model-provider dependencies and the possibility of users accidentally exposing sensitive repository context.
