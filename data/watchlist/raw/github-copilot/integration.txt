•	IDE integration: GitHub Copilot integrates directly into major development environments including Visual Studio Code, Visual Studio and JetBrains IDEs. (https://docs.github.com/en/copilot/get-started/quickstart)
	•	Repository independence: GitHub states that Copilot functionality can work with code hosted on platforms other than GitHub, although GitHub-hosted repositories provide additional context from repositories, pull requests, issues and related GitHub structures. (https://github.com/features/copilot/copilot-business)
	•	API/SDK: GitHub now provides a Copilot SDK for building Copilot-powered applications. The SDK supports TypeScript, Python, Go, .NET, Java and Rust where available and provides authentication, session hooks, integrations and observability capabilities. (https://docs.github.com/en/copilot/how-tos/copilot-sdk)
	•	Backend integration: The SDK can run in server-side applications such as APIs, web backends, microservices and background workers. (https://docs.github.com/en/copilot/how-tos/copilot-sdk/setup)
	•	MCP/plugins: Copilot supports MCP servers and plugins, allowing it to invoke external tools and extend its capabilities. (https://docs.github.com/en/copilot/how-tos/copilot-sdk/features) (https://docs.github.com/en/copilot/concepts/agents/about-plugins)
	•	No-code: GitHub Copilot is not primarily a no-code platform. It is an AI coding assistant/agent integrated into development environments and GitHub workflows. (https://github.com/features/copilot)
	•	Exportability: Git repositories themselves remain standard Git repositories and can be cloned/migrated independently of Copilot. Copilot does not constitute the canonical storage layer for source code. No URL available for this specific characterization.
	•	Leaving Copilot: A company can discontinue Copilot while continuing to use its Git repositories and development environment. However, Copilot-specific configuration, prompts, agent workflows, MCP integrations and organizational policies may need to be recreated in another AI coding platform. GitHub documents these Copilot-specific components and integrations. (https://docs.github.com/en/copilot/concepts)
	•	Model portability: Copilot supports multiple models and even offers BYOK (bring your own key) capabilities, reducing dependence on one underlying model provider. (https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/models)
	•	Model churn: Model availability can change over time. GitHub explicitly states that model availability changes and that new models may take additional time to become available in particular regions or compliance configurations. (https://docs.github.com/en/copilot/concepts/models/fedramp-models)
	•	Upstream dependency: GitHub's 2026 incident history demonstrates that Copilot can be affected by upstream model-provider failures. For example, the May 2026 outage affected multiple OpenAI-backed Copilot models, while the July 2026 incident affected GPT-5.3 Codex. (https://www.githubstatus.com/history) (https://www.githubstatus.com/)
	•	GitHub Actions dependency: Copilot Cloud Agent and Code Review depend on GitHub Actions infrastructure, so an Actions outage can affect Copilot functionality. GitHub explicitly documented this dependency during the July 2026 incident. (https://www.githubstatus.com/index.html)
	•	Breaking changes: GitHub has an active model/version lifecycle, and its documentation requires compatible client versions for certain policies such as FedRAMP model enforcement. Older Copilot extensions/CLI versions may need to be updated to continue using those controls. (https://docs.github.com/en/copilot/concepts/models/fedramp-models)
	•	Overall lock-in risk: MEDIUM. Source-code portability is relatively strong because repositories remain standard Git repositories and Copilot works with non-GitHub-hosted code. However, workflow lock-in is materially higher if an organization adopts Copilot Cloud Agent, GitHub-native code review, MCP integrations, repository indexing, Copilot Spaces, custom agents and other GitHub-specific capabilities. (https://docs.github.com/en/copilot/concepts)
	•	Overall integration assessment: Strong integration / medium lock-in. Copilot's biggest advantage is its deep integration into the existing GitHub + IDE workflow; its biggest vendor-risk disadvantage is that the more deeply an organization adopts GitHub-native agentic features, the more effort is required to reproduce that workflow elsewhere.
