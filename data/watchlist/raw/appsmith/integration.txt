•	Core architecture: Appsmith connects to databases and APIs, provides drag-and-drop widgets and allows application logic to be written using queries and JavaScript. (https://docs.appsmith.com/)
	•	Database/API integrations: Appsmith supports 25+ databases and any API according to its GitHub project description. (https://github.com/appsmithorg/appsmith)
	•	Workflow integrations: Appsmith currently advertises 24+ built-in integrations with databases and SaaS platforms, plus REST and GraphQL APIs. (https://www.appsmith.com/workflows)
	•	AI integration: Appsmith provides a native OpenAI integration supporting Chat Completions, Embeddings and Vision APIs, as well as other AI/data integrations. (https://www.appsmith.com/integration/open-ai)
	•	Deployment: Organizations can use Appsmith Cloud or self-host Appsmith on their own infrastructure. (https://docs.appsmith.com/)
	•	Git integration: Appsmith supports Git-based version control, including branches and rollback, allowing teams to manage application changes through standard development workflows. (https://docs.appsmith.com/)
	•	CI/CD: The current Enterprise plan includes CI/CD, Git repositories, environments and enterprise deployment features. (https://www.appsmith.com/pricing)
	•	Exportability: Appsmith provides Git version control and self-hosting, which substantially improves exit portability compared with proprietary cloud-only low-code platforms. (https://docs.appsmith.com/)
	•	Backup/export: Appsmith's current pricing documentation states that Business and Enterprise support backup and restore synchronized to AWS S3, and Git repositories are available for version-controlled applications. (https://www.appsmith.com/pricing)
	•	Open source: The core Appsmith repository is public and licensed under Apache-2.0 according to GitHub. (https://github.com/appsmithorg/appsmith)
	•	Lock-in advantage: The open-source/self-hosted model gives Appsmith substantially lower platform lock-in than proprietary low-code products because the organization can run the software itself and retain its application source/version history. (https://github.com/appsmithorg/appsmith)
	•	Residual lock-in: There is still some application-level lock-in because applications rely on Appsmith-specific widgets, bindings, queries, JavaScript objects, datasource configurations and workflow constructs. Moving those applications to Retool, Budibase, ToolJet or custom React applications would require some redevelopment. Appsmith's own documentation describes these platform-specific constructs. (https://docs.appsmith.com/)
	•	Known integration/upgrade issues: Appsmith's 2026 releases document breaking changes and fixes, including changes to Docker environment variables and fixes affecting partial exports, Redis datasource security and Git error handling. (https://github.com/appsmithorg/appsmith/releases)
	•	Self-hosting operational dependency: Self-hosting shifts some risk from vendor availability to the customer's own DevOps capability. A user report describes a Docker deployment that failed to recover after a server power outage, illustrating this operational trade-off. (https://www.reddit.com/r/appsmith/comments/1fvk4b8)
	•	Community activity: The public repository remains actively maintained, with more than 20,000 commits and recent 2026 activity. (https://github.com/appsmithorg/appsmith)
	•	Overall lock-in assessment: LOW-to-MEDIUM. Appsmith's open-source licensing, Git integration, self-hosting and standard database/API connectivity significantly reduce vendor lock-in. The principal remaining dependency is the Appsmith application model itself and, for Appsmith AI, the external OpenAI API dependency. (https://www.appsmith.com/integration/open-ai)
