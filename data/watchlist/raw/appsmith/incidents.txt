•	Confirmed security vulnerabilities: Appsmith's public release history shows multiple security fixes in 2026. One release fixed a vulnerability identified as GHSA-qhfj-g87x-m39w, which involved blocking Redis datasource connections to Appsmith's internal Redis instance. The same release addressed 17 security vulnerabilities identified through release-image scans and additional dependency vulnerabilities. (https://github.com/appsmithorg/appsmith/releases)
	•	Additional 2026 vulnerabilities: Appsmith's release history records fixes for CVE-2026-48038, as well as another advisory involving validation of application ownership during partial exports. (https://github.com/appsmithorg/appsmith/releases)
	•	Open security issue: A June 21, 2026 GitHub issue reported Netty CVEs in the Appsmith Community Edition v2.1. (https://github.com/appsmithorg/appsmith/issues/41912)
	•	Security testing: Appsmith says it performs regular third-party vulnerability and penetration testing and uses Snyk, DeepSource and Dependabot for code/dependency analysis. (https://www.appsmith.com/blog/appsmith-has-been-certified-soc-2-type-ii)
	•	Data breach: I found no credible public report of a confirmed Appsmith customer-data breach. Appsmith's Trust Center provides a dedicated data-breach-notification document area, but I found no published breach notification identifying a confirmed customer-data compromise. (https://security.appsmith.com/)
	•	Major cloud outage: Appsmith's official status page currently reports Appsmith Cloud at 99.994% uptime over the displayed 30-day period. (https://status.appsmith.com/)
	•	Outage-history discrepancy: A third-party outage monitor, IsDown, reports several Appsmith incidents in 2026, including incidents on May 14, May 21 and June 11, with one May incident lasting approximately eight hours. (https://isdown.app/status/appsmith) Appsmith's own incident-history page currently reports no incidents for May, June or July 2026, so these third-party detections should not be treated as confirmed Appsmith-posted incident reports. (https://status.appsmith.com/incidents)
	•	Self-hosted operational issue: A Reddit user reported that a self-hosted Docker Appsmith installation failed to recover after a server/power outage. This was a user-specific deployment issue rather than evidence of an Appsmith-wide outage or security incident. (https://www.reddit.com/r/appsmith/comments/1fvk4b8)
	•	Lawsuits: I found no credible lawsuit specifically alleging an Appsmith customer-data breach, security failure or unlawful handling of customer data. No URL available for this negative finding.
	•	Overall incident assessment: MEDIUM security risk rather than high risk. There is a visible stream of vulnerability remediation, including several 2026 issues, but I found no evidence of a confirmed large-scale customer-data breach. Self-hosted customers also inherit responsibility for patching and securing their own deployments.
