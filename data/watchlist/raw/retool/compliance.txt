1. SOC 2
Status: ✅ SOC 2 Type II
Retool states that it maintains a SOC 2 Type II report and provides the report through its Trust Center. (Retool("https://trust.retool.com/?utm_source=chatgpt.com"))
What this means
SOC 2 Type II evaluates whether security controls are:
	•	designed appropriately
	•	operating effectively over a period of time
It is stronger than SOC 2 Type I because it tests ongoing operational effectiveness rather than only control design.
Evidence classification
✅ Independently audited
Retool's SOC 2 Type II report is an external audit artifact, not simply a self-declaration. However, the public Trust Center does not prominently identify the audit firm in the information available without accessing the report itself. (Retool("https://trust.retool.com/?utm_source=chatgpt.com"))

2. GDPR
Status: ✅ GDPR compliant/support claim
Retool states that it is GDPR compliant and includes GDPR among its compliance frameworks. (Retool("https://retool.com/partners/aws?utm_source=chatgpt.com"))
Retool provides enterprise privacy/security documentation covering topics such as:
	•	data protection practices
	•	customer data handling
	•	privacy commitments
Important distinction
GDPR is a legal regulation, not a certification like SOC 2 or ISO 27001.
A company saying "GDPR compliant" generally means:
	•	it has implemented processes intended to satisfy GDPR obligations
	•	it provides contractual mechanisms such as DPAs where applicable
It does not mean an external auditor has certified GDPR compliance.
Evidence classification
⚠️ Vendor claim
I did not find an independent GDPR certification or regulatory attestation for Retool.

What this means
ISO 27001 certifies an organization's:

	•	security governance processes
	•	risk management framework
	•	operational security controls
Evidence classification

However:

4. HIPAA
Status: ⚠️ Conditional / limited support — not a general HIPAA certification
Retool's public documentation does not indicate that Retool Cloud is universally HIPAA compliant.
Available documentation indicates:
	•	customers should not use Retool Cloud for protected health information (PHI) unless appropriate arrangements exist
	•	self-hosted deployments provide additional control because customer infrastructure hosts the data
Retool's terms specifically restrict providing PHI to Retool Cloud and point customers needing PHI handling toward self-hosted deployment options. (Retool("https://cdn.tryretool.com/tos.pdf?utm_source=chatgpt.com"))
A third-party compliance summary also reports that Retool does not provide a standard HIPAA BAA for Retool Cloud and that PHI use cases require careful deployment considerations. (GDPR DPA Atlas("https://dpa-atlas.foundagent.net/vendors/retool?utm_source=chatgpt.com"))
Evidence classification
⚠️ Vendor policy/documentation
