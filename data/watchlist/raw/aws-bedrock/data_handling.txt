**What data is collected and stored**: Amazon Bedrock states it "does not store customer input data or model output data as part of its standard operations". The service does not log prompts or completions. All customer API calls remain within the region they are called from.**Where data is hosted**: Data is processed within the AWS region the customer selects. Bedrock uses dedicated model deployment accounts for each model provider and deploys models within AWS.**Data retention policy**: By default, Bedrock does not retain customer data. However, for certain models (e.g., Anthropic's Fable 5), customers may opt into `provider_data_share`, which sends prompts and outputs to Anthropic for 30-day retention and human review. This has been a point of controversy.**Model training**: AWS explicitly states that customer data is "not used to train AWS models or share them with third parties". "All data that is thrown there is not reused by the model provider for training". *This is AWS's own claim, confirmed in multiple official and community sources.***Subprocessors and third parties**: Bedrock acts as a gateway to third-party foundation models (Anthropic, AI21 Labs, Cohere, Meta, Mistral AI, Stability AI, etc.). For third-party models, "the exact processing path depends on the provider's architecture". While AWS states it does not share data with model providers by default, opting into certain features (like data retention for Fable 5) can make Anthropic a subprocessor with access to customer data.**Policy clarity**: The core policy is clear and consistently stated across AWS documentation and re:Post answers. However, the interplay between AWS's default privacy promises and model-provider-specific opt-in features creates complexity that customers must navigate carefully.
